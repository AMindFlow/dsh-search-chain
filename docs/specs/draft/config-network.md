# 配置、凭据和网络

本规格定义已保存工具条目的网络设置、凭据处理和配置生效边界。官方 DeepSeek 分支按 [DSH-005](dsh-integration.md#dsh-005-deepseek-官方-api-路由)复用宿主配置。

## CFG-001 每条工具的代理与直连

- **要求** 每个自定义条目可以配置自己的 `proxy`。省略或为空白时直连，非空字符串为 HTTP(S) 正向代理 URL，`{ pac: "http://proxy.example:8765/acceleration.pac?v=3" }` 按 [CFG-005](#cfg-005-pac-代理路由)处理。作用范围限于该条目。插件不得改动宿主全局代理或操作系统代理配置。
- **要求** 代理值无效、指定的代理失败或 PAC 失败时，插件须报告相应条目原因，并按 [FB-001](fallback.md#fb-001-自定义顺序与降级条件)尝试下一条。后继条目使用自己的网络设置。
- **来源** [原始需求 R3及新版逐条配置要求 R9](../../project/requirements.md)。
- **验收** 分别配置直连、固定代理和 PAC 的条目，捕获实际路由。断开固定代理时核对该条目无直连请求，下一条按它自己的设置发送。覆盖空值、非法代理和 PAC URL。

## CFG-002 密钥来源和优先级

- **要求** 编辑页允许用户填写该条目的 API key。用户明确保存输入后，用宿主凭据服务保存为该条目的凭据引用。请求期按条目引用、[目录中的进程环境变量](providers.md#cat-001-首期类型)、该名称的 DSH 托管 `refs` 依次解析。OpenAI、Tavily 和 DeepSeek 已有的同名旧版 YAML 顶层项用于最后兼容。纯空白等同于未提供。
- **要求** 只为实际准备尝试的条目解析可用于出站的 key。需要 key 的条目在所有来源缺失时按 [FB-001](fallback.md#fb-001-自定义顺序与降级条件)跳过。需要读取但无法访问或解析的凭据文件须报告配置错误。Bing RSS 无 key。
- **来源** [原始需求 R4及新版编辑和供应商要求 R9、R11](../../project/requirements.md)。
- **验收** 添加同类型但使用不同 key 的两个条目。逐层撤掉条目引用、环境变量和托管 key，核对真正收到的 key。覆盖空值、带引号的 YAML、缺文件、文件损坏和无 key 条目。停用条目不得导致读 key 或出站。

## CFG-003 凭据隔离和脱敏

- **要求** 配置中的凭据字段只保存引用和配置状态。编辑器可接收用户新输入的值，重开时不得回读或回显旧值。key 只随对应供应商鉴权头发送，不得进入其他工具或 PAC 下载请求。日志、返回错误、测试样本和交付产物不得包含实际 key、代理认证、带认证参数的 PAC URL 或原始报错响应体。
- **来源** [原始需求 R4、R5与新增设置面板要求 R9](../../project/requirements.md)。
- **验收** 用可辨识的合成 key 保存并重新打开编辑器。检查配置、设置列表、各供应商与 PAC 请求及诊断记录，密钥只出现在正确供应商的鉴权头中。注入鉴权和代理错误并复查脱敏。

## CFG-004 配置快照与连接释放

- **要求** 宿主插件设置是唯一配置来源，保存有序的 `entries` 列表与 `useOfficialDeepSeekSearch`。条目由稳定 ID、工具类型、名称、启用状态、凭据引用和适用参数组成。保存顺序时更新列表本身。搜索开始时使用已保存快照，后续保存只影响下一次查询。在途请求沿用其配置直到完成或取消，旧连接须在结束后释放，卸载也须释放资源。
- **来源** [原始需求 R3、R7以及新版排序与停用要求 R9、R10](../../project/requirements.md)。
- **验收** 让代理 A 上的查询保持在途，随后改用代理 B、修改顺序和开关并另发查询。核对旧查询继续使用旧快照，新查询使用新配置。关闭或卸载插件后核对本地服务无残留连接。注入保存失败时，已生效快照保持一致。

## CFG-005 PAC 代理路由

- **要求** 显式配置 `proxy.pac` 后，插件须直连获取该 HTTP(S) 地址并保留查询参数。只为实际启动的条目获取或求值。成功加载的脚本可随当前配置缓存，重载时失效。对该条目的目标 URL 与主机调用 `FindProxyForURL`。脚本须在隔离环境运行，可访问的数据限于参数和标准 PAC 助手。加载、求值和建连受该次尝试的预算与取消约束。
- **要求** PAC 支持 `PROXY host:port`、`HTTPS host:port`、`DIRECT`。按脚本顺序尝试。只有确认未向供应商提交查询且主机解析或 TCP 建连失败时，才换下一条路由。直连须由脚本明确给出 `DIRECT`。PAC 下载、求值或路由失败须报告具体阶段。
- **来源** [原始需求 R3、§2、§5、§6及 PAC 补充要求](../../project/requirements.md)。 [PAC 路由顺序](https://github.com/chromium/chromium/blob/main/net/docs/proxy.md#evaluating-proxy-lists-proxy-fallback)
- **验收** 用本地 PAC 服务覆盖三种指令和多候选路由，核对实际目标、路径顺序、请求前建连失败后重选，以及上游已收到查询时无重发。覆盖 PAC 下载失败、脚本无效、取消和配置重载。禁用条目时 PAC 服务的访问次数为零。

## 设计决定

- 传输使用插件自己的 undici dispatcher。直连用独立 `Agent`，固定代理用 `ProxyAgent`。PAC 实现复用能够隔离求值和中止的现成实现。 [undici ProxyAgent](https://github.com/nodejs/undici/blob/main/docs/docs/api/ProxyAgent.md)
- 设置值使用宿主设置表单；凭据复用 dsh 托管服务。只有为旧版项兼容且托管读取无法提供对应层时，才用现成 YAML 解析器只读 `$DSH_HOME/.credentials.yaml`。
