# 设置面板 v4 用户反馈修订（定稿）

来源：Issue #50、PR #51；用户实机反馈（2026-11-26 09:18 +08:00）。观感源头为 DSH 官方「模型」区编辑器截图（SHA-256 前缀 `42035351`）与删除确认截图（SHA-256 前缀 `0006adfb`）。本修订与 `settings-panel-style-lock-v2.md`、`settings-ui.md` 及既有风格条款冲突处，以本文 V4 条文为准；V3 除本文明确替换的位置判据外保持不变。断言目录由 Luna 定稿后逐字嵌入 Oracle，执行脚本仅作忠实转录与驱动，不得更改断言语义。

## V4-1 编辑区在所属条目卡片内就地展开

- **要求** 用户点击某条目「编辑」后，编辑器必须出现在该条目自己的外层卡片内，紧接该卡片的条目行之后；列表内 DOM 中条目行与编辑器相邻可测。其余已持久条目须保持原顺序并整体下移，不得把编辑器渲染到列表末尾、列表外或另一条目卡片内。任一时刻至多一个条目编辑器；切换到另一条目编辑时，唯一编辑器必须移入新目标卡片。取消、成功保存及新建成功后均须关闭编辑器；条目保存仍按 [SET-006](settings-ui-save-granularity-amendment.md#set-006-条目级提交) 只提交该条目，成功提示仍遵循 [SET-007](settings-ui-save-granularity-amendment.md#set-007-成功提示)；持久化、焦点与草稿清理语义不变。新建编辑器仍不进入列表，遵循 V3-1。除旧有「编辑器在列表底部」判据（如存在）由本条替换/废止外，V3 其余条款零改动。
- **来源** Issue #50、PR #51 的用户反馈；截图 `42035351` 显示编辑区展开在当前条目卡片中，后续条目依序排列其下。
- **验收** 在至少三个已持久条目中点击首条「编辑」：观测编辑器属于首条外层卡片且为条目行的紧邻后续 DOM 节点；列表中编辑器总数为一，后续条目的身份与相对顺序不变且位于展开卡片下方。再点击另一条的「编辑」：观测仍只有一个编辑器且其父卡片变为新目标。分别取消、保存编辑并新建成功，观测编辑器关闭、取消不写入、编辑仅该条目持久化且保存成功提示符合 SET-007；新建提交前列表无占位行，提交成功后条目入列。

## V4-2 删除确认使用模态弹窗

- **要求** 用户点击条目「删除」后，必须出现带遮罩的居中模态弹窗，弹窗为 `role="alertdialog"` 且 `aria-modal="true"`。标题必须逐字为「删除 {名称}?」，正文必须逐字为「删除 {名称} 会移除其配置；其使用的凭证（如有）由其他位置管理，将会保留。」弹窗右上须有「×」关闭控件，操作区须有「取消」默认/次级按钮和红色描边 danger 按钮「删除 {名称}」。按钮族沿用现有 `sc-button` 与 danger token（SPC-014/SPC-023）。关闭控件、「取消」或 Escape 均必须关闭弹窗且不得删除、不得改动列表；danger 按钮确认后才可删除该条目。数据层 `requestRemove`/`confirmRemove` 语义及删除后的 `savedNotice` 现状保持不变。废止现有卡片内联确认及旧文案「移除该搜索工具？不会删除宿主凭据。」/「确认移除」。
- **来源** Issue #50、PR #51 的用户反馈；截图 `0006adfb` 显示遮罩、居中白底圆角对话框、标题与说明、右上关闭、取消与红描边删除按钮。
- **验收** 对名称含已知文本的测试条目点击「删除」：读取可见的模态 `alertdialog`、`aria-modal=true`、标题和正文逐字文本、右上「×」、两个按钮逐字文本、次级/危险按钮语义；观测遮罩覆盖视口、对话框居中且圆角非零，并以真实键盘 Tab 验证弹窗控件可达。依次用「×」、取消和 Escape 关闭，各次关闭前后条目 ID/名称列表及 settings mutate 次数均不变。重新打开并点击「删除 {名称}」后，仅目标条目被移除并持久化，其他条目保持，删除成功提示行为不变。

## 设计决定

- V4-1 的「DOM 相邻」定义为编辑器是所属卡片内条目行的 `nextElementSibling`；仅“视觉上看起来在附近”不满足验收。编辑器必须保持卡片内结构，不以 portal 或列表末尾占位替代。
- V4-2 的几何判据只锁定居中（对话框中心相对视口中心误差不超过 2 CSS px）、可见遮罩覆盖视口及边角圆角半径大于零；不钉像素级宽高、边距或具体圆角值，因为截图未提供可靠 CSS 尺寸且视口/宿主缩放会变。浅色表面按可计算的不透明浅白色验收，不做像素截图差分。取消称为「默认/次级」表示默认非危险操作按钮族，不额外推定自动聚焦；键盘可达性独立以真实 Tab/ Escape 路径验收。
- V4-2 不改变 `requestRemove`/`confirmRemove` 数据层协议，不改变 SET-006 条目级提交与 SET-007 提示语义。

## §实现迁移面

实现者处理 `src/client-entry.js` 的卡片/编辑器渲染层：将唯一活动编辑器就地作为所属卡片条目行的相邻节点；切换目标时移动归属而不复制编辑器；新建编辑器继续不入列表。删除渲染从卡片内联确认迁移为遮罩模态，需补齐 `alertdialog`/`aria-modal`、可访问标题与描述、右上关闭、取消/Escape 与确认焦点路径，并沿用 `requestRemove`/`confirmRemove`、danger token 和既有 `savedNotice`。`test/` 需随动覆盖卡片归属/DOM 相邻/顺序、编辑器互斥、关闭及保存、新建无占位行、模态文案和角色、三种取消路径不写入、danger 确认删除持久化；除此迁移面外，V3 相关测试冻结。本文不授权改动源码或测试。
