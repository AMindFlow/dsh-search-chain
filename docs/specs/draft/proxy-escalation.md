# 全局 proxy 升级与条目钉死

本规格定义全局代理升级策略：未配置 `proxy` 的条目（直连态）在直连失败后可按显式全局开关改经一个全局代理出站，以及条目级钉死（仅直连/仅代理）对全局策略的优先关系、升级事件的强制可见性与存量迁移。全部新配置字段存于既有 `search-chain` 行 id / 配置命名空间 / provider id 之下，该标识符永久不变（[HANDOFF-20261128 v0.3.0 红线](../../project/HANDOFF-20261128.md)）。本规格只作用于自定义链的条目循环；官方 DeepSeek 分支（[DSH-005](dsh-integration.md#dsh-005-deepseek-官方-api-路由)）不受影响。

对外承诺口径自本版升级：由「配了代理永不静默回退直连」升级为「**每一次出网路径的改变都可见、可钉死**」。原非对称拒绝承诺对配了固定代理/PAC 的条目继续逐字成立（[CFG-001](config-network.md#cfg-001-每条工具的代理与直连)、PX-003）；新增的升级路径必须显式开启、事件可见、且可被条目钉死否决。

## PX-001 全局升级配置两字段与 secret 处置

- **要求** 顶层配置必须新增且仅新增两个字段：`proxyEscalation`（布尔，升级开关，省略即 `false`，默认 OFF；非布尔含 `null` 一律读闸拒绝，判定并入 [CFG-W-002](config-write-gate.md#cfg-w-002-null-形态矩阵) 矩阵与 [CFG-W-001](config-write-gate.md#cfg-w-001-写闸预检等价性) 两闸等价钉）与 `globalProxy`（全局代理凭据引用名，非空字符串且须符合宿主凭据引用 POSIX 语法，省略即未配置）。`globalProxy` 字段本身只保存引用名与配置状态；全局代理 URL（属带认证信息代理地址，secret 字段）必须只经宿主凭据服务保存（write-only，保存即校验、明文清零），设置器可接收新输入但重开时不得回读或回显旧值。已保存配置或 `user` 层任何位置出现全局代理明文 URL 字段时，写闸必须按 [CFG-W-003](config-write-gate.md#cfg-w-003-写路径明文-key-清零) 同款规则在任意保存路径将其清零，读闸对 `globalProxy` 值为明文 URL 形态（含 `://` 或 userinfo）必须拒绝并提示改由设置面板保存。展示、日志与错误文本中的代理目标必须脱敏为 `scheme://host:port`（去除 userinfo、path、query，沿用 transport `endpointOf` 形态），遵守 [CFG-003](config-network.md#cfg-003-凭据隔离和脱敏)。
- **要求** 全局代理 URL 只在 CONNECT 建隧的 `Proxy-Authorization` 中使用（与条目级固定代理同形态），不得进入其他任何请求头、日志、错误文本或交付产物。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线 a/d；[HANDOFF-20261128 红线第二条](../../project/HANDOFF-20261128.md)。
- **验收** 1. 存量配置不含两新字段时，读闸输出 `proxyEscalation=false`、`globalProxy` 省略。2. 面板保存含认证信息合成 URL（`http://syn-user:syn-pass@syn-proxy.invalid:8080`）后检查宿主配置：仅存引用名与已配置状态，宿主配置、面板回显、日志均不可检索到 `syn-pass` 与 path/query 段；重开编辑器不回显旧值。3. 在 `user` 层注入 `globalProxy` 或同义字段的明文 URL，走面板任一保存路径，断言落盘后无明文字段、请求体不含明文值。4. `proxyEscalation` 取 `null`/非布尔、`globalProxy` 取明文 URL/非 POSIX 名，写闸与读闸双向同拒且错误文本定位字段名。

## PX-002 开关开启但全局代理未配置或不可解析的失败语义

- **要求** 终态形态 `proxyEscalation=true` 且 `globalProxy` 未配置时，写闸与读闸必须拒绝该组合（错误文本定位 `proxyEscalation`，提示先保存全局代理地址），不得落盘。开关开启、引用存在，但请求期引用解析失败、缺失或值为纯空白时，插件不得静默按开关关闭处理：继承态条目照常直连尝试；直连失败须升级时不进行任何代理出站，条目失败原因必须明示「全局升级已开启但全局代理凭据未配置或不可读，未执行升级」并给出可操作指引（在设置中重新保存全局代理地址）。凭据引用解析失败本身遵守 CFG-002 的既有硬失败/未命中分界，不新增静默面。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线 c（绝不静默）；任务书钉死项「开关开但 URL 未配的失败语义」。
- **验收** 1. 面板或直写配置尝试保存「开关开+无引用」终态，两闸均拒绝且错误定位 `proxyEscalation`，零 `settings/mutate`。2. 开关开+引用存在，令凭据服务对引用返回缺失/空白，直连注入 DNS 失败：断言零全局代理出站、条目失败原因含「未配置或不可读，未执行升级」字样。3. 同前置但直连成功：结果照常返回，不出现升级相关文案（升级需求未产生）。

## PX-003 作用域：仅直连态条目，固定代理与 PAC 条目不受全局策略影响

- **要求** 全局升级策略必须且只能作用于按 [CFG-001](config-network.md#cfg-001-每条工具的代理与直连)/[CFG-005](config-network.md#cfg-005-pac-代理路由) 判定为直连态的条目（`proxy` 省略/空白且未配 PAC）。配置了固定代理 URL 或 `proxy.pac` 的条目其出网路径完全自治：全局开关无论开关、全局代理无论配置与否，其请求绝不改经全局代理；其自身代理/PAC 失败仍按 CFG-001 报告并按 [FB-001](fallback.md#fb-001-自定义顺序与降级条件) 降级，绝不改走直连也绝不改走全局代理（非对称承诺逐字保留）。PAC 脚本判定为 `DIRECT` 的路由属该 PAC 条目自治结果，不得因此触发全局升级。
- **要求** 全局升级不得改动宿主全局代理或操作系统代理配置（同 CFG-001 边界）。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 语义与红线 b；任务书钉死项「作用域」。
- **验收** 开关开+全局代理可用，同链配置直连、固定代理、PAC（脚本对目标返回 `DIRECT`）三类条目，向三者注入直连/自身路由故障并另发成功查询：1. 仅直连条目出现升级出站；2. 固定代理条目与 PAC 条目在全局代理本地桩上的请求数为零；3. 固定代理/PAC 条目失败时错误文本不含升级文案，仍按 FB-001 降级下一条。4. 开关关时重放同场景，三类条目出站路径与 v0.2.0 逐请求一致。

## PX-004 「直连失败」触发定义与分类边界

- **要求** 可触发升级的「直连失败」必须限定为：请求提交给供应商之前、按 [FB-005](fallback.md#fb-005-失败分类与排查提示) 判定面归类为 `ENTRY_NETWORK`（直连网络，含其无阶段无状态码兜底路径）的网络层传输失败，即 DNS 解析失败、TCP 连接被拒、连接超时/网络不可达等未离开本机建连面的错误。以下失败必须不得触发升级：供应商业务错误——HTTP `401/403`（凭据或权限）、`402` 或额度证据码（额度）、其他 `429`（限流）、其他 `4xx`（通道参数限制）、`5xx` 与异常响应（`ENTRY_BAD_RESPONSE`）；条目级预算到期（`ENTRY_TIMEOUT`）；内容策略拒绝（`ENTRY_CONTENT_POLICY`，终止类）；凭据解析失败与条目执行期 `CONFIG_*`/`PAC_*` 带码错误（其降级去向按 [FB-006](fallback.md#fb-006-条目执行期带码错误的降级与裸上抛)，但不升级）；宿主取消与总预算耗尽（FB-003 终止面）。判定以既有 `classifyUpstreamFailure` 分类结果为准：仅 `ENTRY_NETWORK` 可升级，其余码一律不升级；已到响应相位（查询可能已提交）的失败不得升级重发。
- **要求** 条目钉死为继承态且开关开启时，一个条目在一次尝试中至多升级一次；升级路由上再次失败时不得回退直连、不得二次升级，条目以其最终失败落定。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 语义「直连失败后从全局代理出」；任务书钉死项「触发定义」。
- **验收** 对直连条目+开关开+全局代理桩，分别注入并逐例核对：DNS 失败、连接被拒、连接超时——三例均触发升级且升级请求实收到；注入 `401`、`402`、`429`、`400`、`5xx`、非法响应体、条目预算到期、内容策略拒绝、缺凭据、宿主取消——九例均零升级出站且 FB-005 分类与降级/终止行为不变。升级路由注入失败：断言无第三次出站（无回退直连、无二次升级）。

## PX-005 升级尝试的预算约束

- **要求** 升级尝试必须共享该条目按 [FB-003](fallback.md#fb-003-预算与取消) 分得的剩余预算：升级发起时点该条目 `budgetMs` 的未消耗时间即升级硬限，剩余 ≤ 0 时不得发出升级请求。总预算 `timeoutMs` 不得因升级延长；FB-003 的条目间预算分配公式与取消语义（条目到期取消在途、宿主取消终止整链）不得因升级改变。因剩余预算不足未升级时，条目失败原因必须明示「直连失败；剩余预算不足，未执行全局代理升级」。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88)；任务书钉死项「预算约束（与 FB-003 关系选定进设计决定）」。选定结论与理由见设计决定「共享剩余预算」。
- **验收** 受控时钟下：1. 条目预算 1000ms、直连失败耗时 400ms，升级请求以 ≤600ms 硬限发出并在预算内完成，整链耗时不超 `timeoutMs`。2. 直连失败发生在预算到期前瞬间（剩余 0），升级零出站、失败原因含「剩余预算不足」。3. 升级在途时条目预算到期，请求被取消、行为等同 FB-003 条目到期。4. 升级不改变后续条目的预算分配值（与无升级基线逐毫秒一致）。

## PX-006 条目级钉死三态与对全局策略的优先

- **要求** 条目必须新增字段 `proxyPin`，三态：`"inherit"`（省略即此，默认）、`"directOnly"`、`"proxyOnly"`。钉死必须优先于全局策略，不得被全局开关或全局代理配置覆盖：`directOnly` 条目即使全局开关开且全局代理有效，也必须仅直连，直连失败即条目失败，绝不升级。`proxyOnly` 条目必须经 `globalProxy` 引用解析出的代理出站且绝不直连——该态是条目级显式意图，不依赖全局升级开关（开关只管继承态的自动升级）；其代理不可用（引用未配置、不可解析、URL 无效）或经该代理请求失败时，条目必须失败且原因明示「条目钉死仅代理：全局代理不可用/失败（脱敏目标）」并零直连出站。`proxyPin` 为非默认值且该条目同时配置 `proxy`（字符串或 `{ pac }`）时，写闸与读闸必须拒绝（语义矛盾：条目自身路由已自治，见 PX-003），错误文本定位条目下标与字段。非法 `proxyPin` 取值（三态之外的任意值、`null`、非字符串）两闸同拒。
- **要求** 钉死为 `directOnly` 的条目，其网络行为必须与 v0.2.0 直连条目逐位一致；钉死为 `inherit` 且开关 OFF 的条目同样必须与 v0.2.0 逐位一致。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线 b；[HANDOFF-20261128 红线第三条](../../project/HANDOFF-20261128.md)。
- **验收** 开关开+全局代理可用：1. `directOnly` 条目注入 DNS 失败——全局代理桩零请求、条目按直连失败落定。2. `proxyOnly` 条目——请求实经全局代理桩收到，直连零出站；断开全局代理桩——条目失败、原因含「钉死仅代理」与脱敏目标、直连零出站。3. `proxyOnly` 且引用未配置——条目失败零出站，原因明示不可用，即使开关为 OFF 亦绝不直连。4. `proxyPin=directOnly` 且条目带 `proxy`、`proxyPin="bounce"` 非法值、`proxyPin=null` 各例两闸同拒且定位 `entries[i].proxyPin`。

## PX-007 升级成功事件的可见性

- **要求** 条目经全局代理升级并成功返回有效来源时，插件必须显性标注该事件，不得静默按普通直连成功呈现：成功结果 `content` 首行（沿用 [FB-002](fallback.md#fb-002-成功结果与提示) 首行机制）必须包含实际使用条目名与「经全局代理升级出站（脱敏目标 `scheme://host:port`）」字样的状态行；调试日志必须记录升级事件（条目 id、脱敏目标），全程遵守 CFG-003 脱敏。`sources` 内容本身不得携带任何代理信息。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线 c；[HANDOFF-20261128 红线第三条](../../project/HANDOFF-20261128.md)。
- **验收** 直连注入 DNS 失败+全局代理桩返回有效结果：1. 返回的 `content` 首行含条目名与「全局代理升级」及脱敏目标 `http://syn-proxy.invalid:8080`，合成认证口令 `syn-pass`、path、query 在 `content`、日志、错误面全部不可检索。2. 未经升级的直连成功结果首行无升级字样（与 v0.2.0 呈现一致）。3. 升级成功时 `sources` 与同结果无升级基线逐字段一致。

## PX-008 升级失败事件的可见性与终态归属

- **要求** 升级发起后失败（含升级路由上的网络层失败、代理认证被拒、升级请求超时）时，条目的尝试记录（`details.attempts`，FB-004/FB-006 面）必须仍按该条目一条记录呈现，条目归因码维持 `ENTRY_NETWORK`，但 `reason` 必须双段可辨：直连失败事实与「本次经全局代理升级仍失败（脱敏目标，失败阶段）」，不得只呈现为纯直连网络失败（那即静默升级）。FB-002 接管提示与终态 `WebError` 文本对该条目的一字概括必须含「升级失败」要素。所有展示遵守 CFG-003 脱敏；不得把升级失败压平为 `ENTRY_PROXY`（该码保留给条目自身代理配置，避免归因混淆）。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线 c；任务书钉死项「成功、失败两种可见性分别写验收」。
- **验收** 1. 直连失败+升级路由连接被拒+链上仅此一条目：终态 `WebError.details.attempts` 恰一条记录，code=`ENTRY_NETWORK`，reason 同时含直连失败与「经全局代理升级仍失败」+脱敏目标，不含认证信息。2. 该条目为前序、后继条目成功：FB-002 首行接管提示对该条目概括含升级失败要素。3. 对比无升级（开关关）同注入：reason 无升级字样——两态文案可区分，升级与否不产生静默。

## PX-009 存量迁移与 v0.2.0 行为逐位一致

- **要求** 本规格必须零迁移脚本落地存量兼容：存量配置不含 `proxyEscalation`、`globalProxy`、`proxyPin` 时，读闸归一化必须等价于「开关 OFF、全局代理未配置、全部条目继承」，运行行为（出站路径、重试次数、预算、状态行、错误文本）必须与 `v0.2.0`（tag 解引用提交 `a603a5b8` 语义）逐位一致，用户零感知、配置零迁移提示。归一化对默认值省略键输出（`proxyEscalation=false`、`proxyPin="inherit"` 与省略同义），存量快照经「读出→保存」round-trip 后除显式写出默认值外不得改变任何既有字段值。降级回滚（v0.3.x→v0.2.0）必须无错：v0.2.0 读闸忽略其未知的顶层/条目字段，行为回退到升级前语义，override 层数据不得因降级保存而丢失非本插件键（[CFG-004](config-network.md#cfg-004-配置快照与连接释放) 既有整体替换键集扩展为含三新键，见设计决定）。
- **来源** [GitHub Issue #88](https://github.com/AMindFlow/dsh-fleetseek/issues/88) 红线（存量零感知）；[HANDOFF-20261128 红线第一条](../../project/HANDOFF-20261128.md)。
- **验收** 1. 用 v0.2.0 真实形态存量 fixture（含直连/固定代理/PAC 三态条目与超时/官方开关）跑 v0.3.0 读闸与整链：输出与行为逐位一致，无升级出站、无新状态行。2. 存量快照 round-trip 保存后 diff 仅允许新增显式默认键（若有），既有键值零变化。3. 开启升级并保存后以 v0.2.0 读闸加载同 override 层：无 `CONFIG_INVALID`、行为回 v0.2.0（开关被忽略、无升级）；他插件顶层键原样保留。

## PX-010 出网承诺文案（Discover/README 最小句）

## 设计决定

- **PX-001（全局代理以凭据引用入配置）**：`globalProxy` 顶层字段只承载引用名（面板固定写入合法 POSIX 引用名，如 `search_chain_global_proxy`），明文 URL 走 `credentials/set` 通道——复用 CFG-002/CFG-003 已验证的 write-only 闭集模式，而非把 secret 放宿主设置行。理由：宿主设置行无「重开不回显」保证，且 CFG-W-003 的 SECRET_FIELD 清理只兜底、不能当存储面；实现时全局代理明文字段名须并入写闸清理闭集。明文 URL 形态在 `globalProxy` 上被拒是防呆（提示走面板），不是安全边界。
- **PX-005（共享剩余预算，选定）**：升级共享条目 FB-003 预算的未消耗时间，不重置。备选「升级重置预算」被否：FB-003 总预算 `timeoutMs` 是宿主侧硬契约与红线级不变量，重置会使单条目实际出网上限翻倍、并需改动 FB-003 条文（越出本包范围）。共享语义同时天然满足「剩余为 0 不升级」，与「升级不得延长总预算」互为推论，无需第二条款。
- **PX-006（钉死仅对直连态条目合法；proxyOnly 与全局开关正交）**：全局策略只作用于直连态（PX-003），故钉死只对直连态条目有意义；与自有 `proxy`/PAC 共存的组合被两闸拒绝，避免出现「钉死看似覆盖自有代理、实际行为不变」的假承诺面。`proxyOnly` 不依赖 `proxyEscalation`：开关是「自动升级」的全局保守默认，钉死是条目级显式指令，二者语义正交；「不被全局策略覆盖」双向成立（开关开不覆盖仅直连，开关关不剥夺仅代理）。
- **PX-007/PX-008（升级 = 条目内传输层重试，attempts 单记录、码不换）**：升级视作同一条目内在预算内的一次改道重试，`attempts` 仍按条目一条、归因码维持 `ENTRY_NETWORK`，升级事实进 `reason` 与状态行。理由：FB-004/FB-006 终态结构与 `attempts` 契约按条目建模，若升级另记一条会破坏既有终态断言面并与 #86（key 池轮替同样在条目内重试）的归因模型冲突；保留 `ENTRY_PROXY` 给条目自有代理，避免「代理失败=用户配错代理」的误导排查方向。可见性红线由 reason 双段与状态行承担，不靠拆记录。
- **PX-007（状态行挂 FB-002 首行机制）**：升级状态行复用 FB-002「`content` 首行标明实际使用情况」的既有呈现通道（宿主时间线可见、无需新协议面），不新增结果字段，避免宿主 `WebResult` 形状变动的跨包依赖。
- **PX-010（包间依赖：#102）**：README 全面文案翻新归 #102。依赖方向：#102 引用本规格的新承诺口径为真值文本；#88 只替换出网承诺直接相关的最小句，避免两包在同一文件上产生合并冲突——#88 先行合入，#102 rebase 后做全文翻新。仓库外渠道（market-index、Discussion #14418、dshopen #830）文本按 HANDOFF 发布配方在发布或 #102 收口时同步，非 #88 合入门槛。
- **PX-011（面板不做连通性探测）**：「保存即校验」对本字段取「语法校验+凭据写入成功」口径；对代理做 CONNECT 探测属真实外网行为，与 SET-004 面板零出站边界冲突，且会把探测流量泄给可能未启用的代理。可达性反馈由升级事件（PX-007/PX-008）在真实搜索中承担。
- **PX-009（CFG-004 键集扩展）**：`writeConfig` 的自有顶层键集（`OWN_CONFIG_KEYS`）扩展为含 `proxyEscalation`、`globalProxy`；条目新字段 `proxyPin` 入条目已知字段集（`HANDLED_ENTRY_FIELDS`），非默认值须显式保留、默认值省略输出。降级兼容靠 v0.2.0 读闸对未知键的既有透传/忽略行为，不加降级专用代码。
