## 对 SET-004 的修正

[SET-004](settings-ui.md#set-004-保存与凭据状态) 的下列面**原样保留**：读写同一份宿主配置（CFG-004）、保存成功后才确认生效、失败保留未提交编辑并显示可操作错误、条目状态只表示本地配置与启用情况、面板操作零供应商请求。其「保存」的**边界**由「一次全量提交」修正为「按条目与离散动作独立提交」，由 SET-006 承接；其余条文不改写。

## SET-006 条目级提交与离散落盘

- **要求** 面板不得存在全局保存按钮或任何跨条目批量保存入口（`data-role="save"` 与 `.sc-save-button` 废止）。条目编辑器动作行必须为左「取消」右提交主按钮（样式=风格锁定表 v1 SPC-014 standard 档 + SPC-022，禁 compact 档）；文案固定：取消=`取消`（废止「完成」），编辑提交=`保存`/进行中 `保存中…`，新建提交=`创建工具`/进行中 `创建中…`。提交钮必须对该条目全量提交：新建=完整校验、有新 key 先写凭据、带 `expectedRevision` 的设置变更，仅当成功后以启用状态追加至持久列表末尾并关闭编辑器；编辑=按稳定条目身份合并该条目全部受管字段后提交；提交载荷不得夹带其他条目或全局字段的未提交草稿。提交进行中提交钮禁用并切进行中文案，输入与取消钮同时禁用；除此以外的任何状态（只读、缺 revision、校验失败、上次提交报错），取消钮必须可点击，点击不得写入配置，且必须显式清除该条目字段草稿与明文 key 缓冲、关闭编辑器、焦点归还触发控件。顶部开关切换、超时输入失焦或回车且值变更并通过校验、卡片启用开关、确认移除、拖拽或键盘排序，均必须立即以最新持久快照为底板发起仅含该离散变更的独立提交，遵守「成功才确认生效、失败保留意图并报错」。
- **来源** Issue #50 用户目检追加评论（对齐官方模型区粒度，用户拍板）；官方 `EditorFooter.tsx` 头注释（dismiss on the left, commit on the right；"Cancel refuses input only while a commit is in flight, never because the card is disabled"）与模型区无全局保存按钮的负例实证；Hydrogen High 裁定 R1-1a/b/c/d（`/tmp/agy-log-v2-1.txt`）。
- **验收** DOM 无 `data-role="save"`。新建条目填字段与临时 key 后提交：成功后条目出现在列表末尾且启用，其余未提交条目不落盘；编辑仅提交该条目；注入校验失败/凭据失败/版本冲突时编辑器不关闭、输入不丢、错误可见且宿主继续运行旧快照。只读态下取消钮可点。顶部开关、超时（合法/非法）、启用开关、排序、确认移除逐项操作，均无需全局按钮即单独落盘；失败时错误可见且持久快照不变。

## SET-007 保存状态反馈位置

- **要求** 面板底部状态区撤除。保存成功提示必须显示在节级顶部槽位（区标题与说明、只读提示之后，工具卡片列表之前），使用 `role="status"` 与 `aria-live="polite"`；条目保存成功文案含目标名称（`已保存 ${名称}。`），全局字段与离散动作用 `已保存设置。`。编辑器内提交产生的校验、凭据或版本冲突错误必须就近渲染在编辑器动作行上方（`role="alert"`）；面板加载失败、缺 revision、以及非编辑器发起操作的失败必须显示在同一节级顶部槽位（`role="alert"`，与成功提示互斥）。样式沿用 v1 SPC-004/SPC-030 已钉值（12px/18px 与状态色 token），不发明新数值。
- **来源** 官方 `ModelsSection.tsx` `savedNotice` 逐字（节级位置、`role="status" aria-live="polite"`、`savedProvider: '已保存 {provider}。'`）；错误位为类推（SET-004 错误可操作可见约束 + 官方错误横幅样式未获取，见 v2 开放问题 O-13）；Hydrogen High 裁定 R1-1e。
- **验收** 条目保存成功后提示出现在列表上方且播报一次；编辑器提交失败时错误出现在编辑器动作行上方而非面板底部；面板底部不再出现任何状态节点。

## SET-008 跨分区草稿保全

- **要求** 必须在面板组件之外的模块作用域维护内存级草稿缓存，以条目身份为键（未提交新增分配稳定临时身份），记录编辑模式（新建/编辑）、字段快照、内存态明文 key 缓冲与起草时的持久快照版本号 `baseRevision`；全局字段用独立键承载（超时输入必须纳入；顶部开关仅在提交失败或进行中驻留未确认目标值与错误上下文）。不得把未提交草稿或明文密钥写入宿主配置或任何浏览器本地存储。编辑器字段变更与超时输入变更必须同步写入缓存；仅当该键提交成功或用户显式点击「取消」时清除对应缓存；分区切换导致的组件卸载与后台刷新不得清除缓存，也不得用持久快照静默覆盖缓存字段。面板重挂载并取得最新持久快照后必须逐条校验：版本一致则回填（含未提交新增与活跃编辑目标）；版本冲突或原编辑条目已被外部删除时，不得静默丢弃草稿、不得静默换版本重放，必须在面板或编辑器内显示版本冲突告警（`role="alert"`），仅允许用户显式「取消」放弃草稿或确认覆盖后显式重提。
- **来源** 用户追加要求「切分区不丢未保存信息」。官方基线实证：编辑器与字段草稿全部为组件局部状态、持久 store 仅存已保存快照，官方仅以「addMode 面板保持挂载（`hidden` 兜底）」「后台刷新 preserve its drafts」「`expectedRevision` 版本锁」三招对抗区内丢草稿——官方对切分区卸载本身无保全承诺（shell 挂载策略未获取，v2 开放问题 O-1）。本条为超出官方基线的**类推延伸**（锚：preserve its drafts + expectedRevision 语义，延伸至卸载-重挂载场景），经 Hydrogen High 裁定 R1-2 授权成立。
- **验收** 编辑器输入名称与临时 key（或改超时）后不提交，切至其他设置分区再切回：输入与明文 key 缓冲完整保留（重挂载恢复编辑态或草稿指示按 O-6 拍板形态验收）。模拟切分区期间外部使快照版本递增：切回后草稿未丢且出现冲突告警，不发生静默覆盖远端；显式取消后缓存清空，再次切回不再回填。全程无草稿或明文 key 出现在宿主配置文件与 `localStorage`/`sessionStorage`。

## 设计决定（备案）

- 官方设置体系并存两种粒度：模型区每卡提交（`EditorFooter`）与网页搜索区表单级 `SettingsForm`（原语未分发，视觉未获取）。用户拍板对齐模型区，本修正案据此执行；若未来引入 `SettingsForm` 同形场景，须另立修正案。
- 卡片编辑器的「未提交即丢弃」是官方基线（dismiss=卸载弃稿）；SET-008 的模块级缓存是用户显式要求的增量能力，非官方复刻，实装机评审时不得作为「与官方不一致」的缺陷提出。
