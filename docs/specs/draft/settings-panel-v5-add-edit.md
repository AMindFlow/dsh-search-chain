# 设置面板 v5 增加/编辑交互修订（草案）

来源：Issue #56，用户四项反馈（编辑开关收起、添加入口原位成表单、入口互斥、开关文字精简）+ codex 复审 P2 草稿可达性（V5-5，已追加为验收项）；宿主「模型」区交互为图例基准。本修订与 `settings-ui.md`、`settings-panel-v3-feedback.md`、`settings-panel-v4-feedback.md` 及风格锁定条款冲突处，以本文 V5 条文为准（其中风格锁定 SPC-025 内嵌 picker 目标面由 V5-2 废止，见「§目录影响清单」）。验收判据目录为 `test/settings-panel-add-edit-v5.test.js`（GPT-6 Luna High 编制，SHA-256 `674c9f0b…1210`，基线 4/4 红）；判据冻结，进入本包后一个字节不得更改、语义不得改写。硬约束：V4-1 编辑器卡片归属、V4-2 删除模态、SET-005/SET-006/SET-007/SET-008 语义与 P0 凭据边界零回归。

## V5-1 编辑开关：同一条再点「编辑」即收起

- **要求** 用户点击某条目「编辑」后，必须打开该条目的配置表单（保留现有就地展开语义）；再次点击同一条的「编辑」必须收起表单。开/收全程零持久化写入（settings/mutate 计数为零）。既有语义必须保留：SET-008 跨分区草稿缓存与取消语义（取消 ≡ 丢弃）。收起不清草稿：该条目草稿字段与缓存记录保留，重开编辑器或重挂时可复原；「丢弃」语义仍仅由取消 / Escape 承载。
- **来源** Issue #56 用户反馈第 1 项。
- **验收** 三条已持久条目夹具中，点击条目 B「编辑」：观测恰一个编辑器；再次点击同一条目 B 的「编辑」：观测编辑器数为零、settings mutate 计数为零。

## V5-2 添加入口原位成表单

- **要求** 用户点击「＋ 添加搜索工具」必须直接在列表下方入口原位打开新增表单（入口本身被表单替换；提交前列表不得出现占位行）。表单必须含厂商下拉框；厂商集为现有 CATALOG_UI 全部 8 种类型，各厂商标签（计费说明语义）必须出现在对应选项文本中。选定厂商后，表单字段集与凭据规则必须与现有编辑表单完全一致：需 key 厂商显示 key 与 credentialRef 两个字段；免 key 厂商（bing）两个字段皆不显示。取消或保存成功后，表单必须关闭、入口必须恢复；打开表单不得提前创建持久条目；名称空白不得通过名称门（提交禁用或显示名称门错误，两者之一）。废止旧「点添加 → sc-picker 选厂商」独立步骤及其 picker 控件。
- **来源** Issue #56 用户反馈第 2 项；宿主「模型」区添加入口原位成表单的交互为图例基准。
- **验收** 三条条目夹具中，点击「添加搜索工具」后观测：恰一个编辑器；编辑器在列表最后一张卡片之后的入口区域原位展开；列表卡片顺序与持久条目数均不变；「添加搜索工具」入口不在场。表单内切换厂商为免 key 厂商：观测字段集不含 key 与 credentialRef；再切换为需 key 厂商：观测 key 与 credentialRef 均在场。取消后观测：表单关闭、入口恢复、持久条目数不变、写入次数为零。再次打开、选择免 key 厂商、以空白名称提交：观测被阻断（提交禁用或名称门错误）；输入合法名称后保存：观测表单关闭、入口恢复、持久条目数 +1 且立即进入列表视图、恰一次 mutate。

设计决定：

- 厂商下拉框默认选中 CATALOG_UI 顺序的第一种类型（openai）；幽灵条目默认名称取该类型显示名。下拉框仅出现在新增表单；持久条目的编辑表单不提供厂商切换（改持久条目类型不在本包范围）。
- 下拉切换时的草稿字段迁移规则：名称仍等于旧厂商默认名（即用户未修改）时跟随新厂商默认名；用户已修改的名称原样保留；credentialRef 与 key 明文缓冲原样保留（免 key 厂商下隐藏，切回需 key 厂商时恢复可见），SET-008 缓存记录的 type 同步更新。
- 新增表单复用既有幽灵条目链（addEntry 草稿追加、submitEditor 条目级提交、cancelEditor 丢弃、SET-008 缓存复原）；仅改入口（点添加即建幽灵并开编辑器）与位置（幽灵编辑器渲染于入口区域原位，不再置于列表尾部）。
- 「新增表单打开」不作为模型独立开关，由「当前编辑器条目为未持久（幽灵）条目」派生——含 SET-008 重挂复原自动重开的情形；幽灵编辑器在场即入口不在场，避免标志与现实分叉。

## V5-5 切走后重开新增 = 恢复同一待保存草稿

- **要求** 用户在新增表单（未持久幽灵条目）上输入了未保存字段后，切换去编辑任一既有条目：该切换不得产生任何持久化写入，且待保存草稿必须保留；再次点击「＋ 添加搜索工具」入口必须重开**同一**待保存草稿——条目 id 不变，名称 / 厂商类型 / credentialRef / key 明文缓冲全量回填，厂商下拉框选中值为切走前厂商。在该草稿上显式保存必须按正常新增行为落盘（条目进入持久卡片列表、恰一次 mutate）。显式取消该草稿后，再次点击新增入口必须创建全新草稿（全新 id + 厂商默认字段，无取消前字段残留）；无待保存草稿时点击新增入口每次都创建全新草稿（现状的反面保护）。
- **来源** codex 复审 P2（草稿可达性：切走再切回后待保存新建草稿不可达、只能丢失或重复建单）+ 用户「草稿不丢」诉求；Issue #56 已追加 V5-5 为验收项。
- **验收** 三条已持久条目夹具：以新增表单建 tavily 草稿（输入名称与 credentialRef，零写入）→ 切换编辑既有条目（零写入）→ 再点新增入口：观测编辑器绑定 id 与切走前草稿 id 相同、名称与 credentialRef 回填、零写入；点保存：观测恰一次 mutate、条目进入持久卡片列表、持久名称与 credentialRef 与草稿一致。再建新增草稿、输入名称、取消（零新增写入）：观测再点新增入口得到全新 id、名称非取消前值、credentialRef 为空、零写入。反面：无待保存草稿时连续两次新增观测 id 不同、名称与 credentialRef 均为厂商默认值、全程零写入。
- **判据** `test/settings-panel-draft-reach-v5.test.js`（GPT-6 Luna 编制，call-7 勘定；红线 = 重开必须恢复同一草稿 id + 字段，强制结算方案已被否决）。实机行由 Luna R3 勘定。

设计决定：

- 待保存草稿的判定面 = 内存草稿列表（`model.draft.entries`）中不在有效持久视图内的条目（与 `editorIsCreate` / V5-3 互斥 / 卡片幽灵过滤同一幽灵判定）。草稿行是字段值的活来源（key 明文缓冲在 `model.keys`）；SET-008 重挂路径先把 create 缓存记录物化回草稿行（`draftCacheApply`）才进入交互，故判定面与缓存无分叉；缓存记录本身不因重开而改动（重挂复原路径不受影响）。
- 重开 = `editingId` 切回幽灵 id（表单即幽灵编辑器，不新分配 id、不重置字段）；显式保存 / 取消是删除待保存草稿的唯一路径（现有语义），开/收与切换路径不得删除。

## V5-6 厂商下拉选项纯名与计费提示行联动

- **要求** 新增表单的厂商下拉框（`select.sc-select-input`）各 `<option>` 文本必须仅为纯厂商名（`CATALOG_UI` 第二元素 `label`），不得包含括号包裹的计费说明。同时在厂商下拉框正下方必须渲染一行「当前所选厂商计费提示」（`<p class="sc-billing-hint" data-role="billing-hint">`），文本等于 `CATALOG_UI` 当前所选厂商第三元素 `billing` 原文（不加括号包裹），并随厂商下拉切换实时联动更新。该提示行仅在新建（幽灵）编辑器路径显示；编辑已持久条目时不得显示。
- **来源** 用户实测反馈 + Issue #56 评论。
- **验收** 打开新增表单，观测下拉框全部 8 个选项 `textContent` 均等于对应纯厂商名且不含「（」「计费」；观测 `.sc-billing-hint`（`data-role="billing-hint"`）存在且等于当前选中厂商（默认 `openai`）的 `billing` 原文；切换厂商（如 `exa` → `bing` 及遍历全部 keyed/bing 类型）后，观测 `.sc-billing-hint` 文本实时联动更新为对应厂商 `billing` 原文；切换去编辑任一已持久条目，观测编辑器内不存在 `.sc-billing-hint`。

## V5-7 代理配置暴露

- **要求** 编辑器（新建与编辑两条路径都显示）在既有表单字段之后新增高级折叠区：`<details class="sc-advanced">`，`<summary>` 文本「网络代理（高级）」；区内含 label「代理」+ 输入框（`class="sc-input"`、`data-role="proxy-field"`、`data-field="proxy"`、`data-entry-id`=当前编辑条目 id）+ 一行小字说明「留空=直连；填 http(s)://host:port；PAC 填 pac:http(s)://…」。三态语义：输入值以 `pac:` 开头 → 存 `{ pac: 去前缀后 URL }`；其余非空 → 存 URL 字符串；留空 = 直连（删除字段）。**只写不回显**（CFG-002 类 key 政策，含认证参数）：条目已持久 proxy 时，输入框 `value` 必须为空字符串、`placeholder="已配置（输入新值覆盖，清空并提交=删除）"`、元素带 `data-configured="true"`；未配置时 `placeholder="留空=直连"`。任何渲染路径不得把 proxy 值（含 user:pass）写进 DOM 文本或属性。提交语义：输入未被触碰 → 条目原 proxy 字段原样保留（undefined 保留 undefined、原值保留原值）；触碰后空串 → 提交时删除该条目 proxy 字段；触碰后非空 → 按上述形态写入。`normalizeProxy`（`src/client-entry.js` 内联纯函数面）是唯一校验权威，错误文案原样透出到既有保存错误面（编辑器动作行上方 `role=alert`）。keyless 条目（bing）同样可配代理，与 `editorCredInputs` 凭据逻辑正交（上轮 P2 修复语义保持）。保存成功后折叠区随编辑器关闭收起；再次进入编辑器回到「未触碰 + 已配置态」placeholder。
- **来源** 用户 2026-11-26 指令（本版本交付可用代理）+ Issue #58（#57 后续：面板暴露条目级代理配置，CFG-001 UI 缺口）；范围钉：本单只做面板暴露三态输入与只写不回显，出站实现由 #61 承接。
- **验收** `test/settings-panel-proxy-ui.test.js` 八用例（GPT-6 Luna 惯例替身，复用 `test/helpers/settings-panel-v02.js`）：a) 新建与编辑两条路径的编辑器都存在高级区与 proxy 字段（初始未触碰 + 未配置态 placeholder「留空=直连」）；b) 新建填 `http://127.0.0.1:8192` 保存 → 持久条目 `.proxy` 为该字符串（恰一次 mutate）；c) 编辑填 `pac:http://x/y.pac` 保存 → 条目 `.proxy` 为 `{ pac: "http://x/y.pac" }`；d) 编辑已含 proxy 的条目 → 输入框 `value===""`、`data-configured=="true"`、placeholder 含「已配置」，且渲染树（文本与全部 props 字符串）不含该 URL 文本；e) 不触碰输入直接保存 → proxy 原值原样保留；f) 触碰并清空提交 → 条目无 proxy 字段；g) 非法值（如 `127.0.0.1:8192` 缺协议）→ 保存报错含 normalizeProxy 文案（「必须是绝对 HTTP(S) URL」）且不落配置（零 mutate、原值不变）；h) bing 条目配 proxy 保存 → 持久条目有 proxy、无 `credentialRef`/`key` 字段。

设计决定：

- 代理输入明文缓冲为模型级 `proxyTexts`（entryId → 文本），与 `model.keys` 同生命周期（仅触碰后建档；成功提交/显式取消清除；后台读回与切换条目不清）；不进 SET-008 草稿缓存（缓存记录 shape 不变）。
- 提交候选经 `candidateEntriesFor` 新增 proxyIntent 第三语义（null=原样保留 / {proxy}=覆盖 / {removeProxy}=删除）；与 `editorCredInputs` 正交。绑定守卫 `singleEntryDiff` 的 `sameRow` 判据不变（proxy 不参与行身份比对）。
- 实时校验门 `editorBlock` 同样纳入触碰后的代理值（与名称门/凭据门同判据）；非法值期间提交钮禁用，提交时兜底同判据，错误经既有保存错误面原样透出。
- 说明行使用专用类 `.sc-proxy-hint`（不复用 `.sc-billing-hint`）——V5-6 判据钉「编辑路径零 `.sc-billing-hint` 节点」，专用类实现零迁移。

## §实现迁移面

实现者处理 `src/client-entry.js` 的卡片 / 编辑器 / 添加入口渲染层：`openEditorFor` 改为开/收语义（同 id 翻转、零写入、草稿与缓存保留）；添加入口直接建幽灵并开编辑器（废止 `addOpen` picker 步骤），幽灵编辑器渲染于入口区域原位，新增表单内加厂商下拉框（选项文本 = 厂商显示名 + 计费说明），类型切换后字段集与凭据规则与编辑表单完全一致（免 key 厂商 key 与 credentialRef 皆隐藏）；幽灵编辑器在场时添加按钮不渲染，关闭后经 ref 回焦；卡片开关「启用」文字 span 删除（官方行不动）。`test/settings-panel-v02.test.js` 仅迁移直接驱动旧流程的 SET-002 判据操作步骤（断言原样）；其他既有用例不得触碰。本文不授权修改 v5 判据文件。
